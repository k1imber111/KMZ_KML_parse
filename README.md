# KML/KMZ Placemark Organizer

Утилита для группировки меток (`Placemark`) в файлах **KML** и **KMZ** по папкам.
Основной сценарий: вы выбираете файл, задаёте имя папки и перечень меток,
после чего создаётся **новый KMZ-файл**, содержащий только выбранные папки и метки.
Исходный файл **не изменяется**.

## Возможности

- Работа как с `.kml`, так и с `.kmz` файлами.
- Интерактивное меню: выбор между запуском и просмотром инструкции.
- Выбор файла через путь или передачей аргумента командной строки.
- Два режима ввода названий меток:
  - интерактивный — по одной метке за раз;
  - пакетный — **через запятую и/или двоеточие** (например: `32:33:34, 40, 41:42`).
- Поиск по точному названию метки и по маске (`*`, `?`).
- Стили и иконки меток переносятся в результат.
- Автоматическое логирование в `kml_manager.log` и вывод в консоль.

## Установка и запуск

Требуется Python 3.8+. Сторонние библиотеки для запуска не нужны.

```bash
python KMZ_new.py
```

Также можно сразу указать путь к файлу — он будет использован для первого запуска из меню:

```bash
python KMZ_new.py "C:\Путь\к\файлу.kmz"
```

На Linux путь будет стандартным Unix-видом:

```bash
python KMZ_new.py "/home/user/maps/marks.kml"
```

Путь, вставленный через «Копировать как путь» (в кавычках), принимается как есть.

### Сборка exe

```bash
python -m PyInstaller KMZ_new.spec --noconfirm --clean
```

Результат — `dist/KMZ_new.exe`.

### Самопроверка

```bash
python test_kml_organizer.py
```

## Структура проекта

- `KMZ_new.py` — тонкая оболочка-скрипт для запуска CLI.
- `KMZ_new.spec` — конфигурация сборки PyInstaller.
- `test_kml_organizer.py` — самопроверка на `assert`, без сторонних библиотек.
- `kml_organizer/`
  - `core.py` — низкоуровневая работа с KML/KMZ: парсинг, поиск меток, построение экспортного документа.
  - `services.py` — сервисный слой: загрузка документа и экспорт в отдельный KMZ.
  - `io_utils.py` — безопасный ввод/вывод и диалог с пользователем.
  - `cli.py` — логика интерактивного меню и основной сценарий работы.
  - `logging_config.py` — конфигурация логирования.

## Поиск меток

Каждое введённое название сначала сравнивается с названием метки **точно**.
Пробелы по краям игнорируются, регистр учитывается.
Если точного совпадения нет, а в названии есть символы маски, оно применяется как маска:

| Маска | Значение | Пример |
|---|---|---|
| `*` | любое количество любых символов | `10*` → `10`, `100`, `10А` |
| `?` | ровно один любой символ | `1?` → `10`, `11`, `1А` |
| `[...]` | один символ из набора | `1[05]` → `10`, `15` |

Маски работают в обоих режимах ввода и для любого количества названий в строке.
Названия, по которым ничего не найдено, программа перечисляет отдельно.

## Формат пакетного ввода меток

В пакетном режиме вы можете вводить названия меток в одной строке:

- через запятую: `10,11,12`
- через двоеточие: `10:11:12`
- комбинированно: `10:11,12:13,14`

Разделители `,` и `:` считаются равнозначными и используются только как разделители
между отдельными названиями. Пробелы по краям игнорируются.
Метку, в названии которой есть запятая или двоеточие, вводите в интерактивном режиме.

## Папки и метки

- Каждая метка попадает **только в одну папку**. Если метку добавить во вторую папку,
  она переедет туда — программа сообщит, сколько меток перенесено.
- Чтобы завершить набор папок и сохранить файл, нажмите `ENTER` вместо имени папки
  или ответьте «нет» на вопрос «Создать еще одну папку?».

## Результирующий KMZ-файл

- Исходный KML/KMZ не модифицируется.
- По завершении работы создаётся новый файл рядом с исходным, с именем вида:
  - `input.kmz` → `input_groups.kmz`
  - `input.kml` → `input_groups.kmz`
- Если файл с таким именем уже есть, он перезаписывается.
- Внутри архива:
  - `doc.kml` со структурой `<kml>` → `<Document>` → `<Folder>` → `<Placemark>`;
  - общие стили исходного документа (`Style`, `StyleMap`, `Schema`);
  - вложения исходного KMZ (иконки из `files/` и т.п.).

## Логирование

- Логи пишутся в файл `kml_manager.log` в текущей директории; в консоль выводится только текст сообщений.
- В логах фиксируются:
  - успешная загрузка и разбор файлов;
  - количество найденных, добавленных и перенесённых меток;
  - ошибки парсинга XML, проблемы с файлами KMZ/KML и другие исключения.

## Команды и обработка ошибок

- `!cancel` — отмена текущего шага; на вводе имени папки — завершить набор и сохранить файл.
- `!exit` — немедленное завершение программы **без сохранения** набранного.
- При ошибках чтения, разбора или записи вы получаете понятное сообщение и запись в логе.
- Файл в кодировке Windows-1251 с неверно указанной в заголовке кодировкой читается без потери букв.
