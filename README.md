# KML/KMZ Placemark Organizer

Утилита для группировки меток (`Placemark`) в файлах Google Планета Земля — **KML** и **KMZ** — по папкам.
Основной сценарий: вы указываете файл или папку с ним, задаёте имя папки и перечень меток,
после чего создаётся **новый KMZ-файл**, содержащий только выбранные папки и метки.
Исходный файл **не изменяется**.

## Возможности

- Работа с `.kml` и `.kmz` в разных вариантах (см. «Какие файлы открываются»).
- Путь к файлу или к папке; кавычки вокруг пути убирать не нужно.
- Два режима ввода названий меток:
  - интерактивный — по одной метке за раз;
  - пакетный — через запятую, двоеточие или точку с запятой (например: `32:33:34, 40; 41`).
- Поиск по точному названию, по номеру в начале названия и по маске (`*`, `?`).
- Стили и иконки меток переносятся в результат.
- Прошлые результаты не перезаписываются.
- Логирование в `kml_manager.log` и вывод в консоль.

## Установка и запуск

Требуется Python 3.8+. Сторонние библиотеки для запуска не нужны.

```bash
python KMZ_new.py
```

Путь можно передать сразу — к файлу или к папке. Он будет использован для первого запуска из меню:

```bash
python KMZ_new.py "C:\Путь\к\файлу.kmz"
```

```bash
python KMZ_new.py "C:\Путь\к\папке"
```

### Сборка exe

```bash
python -m PyInstaller KMZ_new.spec --noconfirm --clean
```

Результат — `dist/KMZ_new.exe`. На exe можно перетащить файл или папку мышью.

### Самопроверка

```bash
python test_kml_organizer.py
```

Если рядом лежит папка `Образцы файлов` с реальными KML/KMZ, самопроверка прогонит и их.
В репозиторий эта папка не попадает.

## Структура проекта

- `KMZ_new.py` — тонкая оболочка-скрипт для запуска CLI.
- `KMZ_new.spec` — конфигурация сборки PyInstaller.
- `test_kml_organizer.py` — самопроверка на `assert`, без сторонних библиотек.
- `kml_organizer/`
  - `core.py` — работа с KML/KMZ: чтение, поиск меток, построение экспортного документа.
  - `services.py` — сервисный слой: загрузка документа и экспорт в отдельный KMZ.
  - `io_utils.py` — ввод пользователя, разбор пути, поиск файлов в папке.
  - `cli.py` — интерактивное меню и основной сценарий работы.
  - `logging_config.py` — конфигурация логирования.

## Путь к файлу

Программа принимает путь к файлу `.kml`/`.kmz` или к папке, где он лежит.

- Кавычки по краям (`"…"`, `'…'`, `«…»`) и лишние пробелы убираются автоматически.
  Путь из «Копировать как путь» вставляется как есть.
- Раскрываются переменные окружения (`%USERPROFILE%\Desktop`) и `~`.
- Если указана папка:
  - один подходящий файл — он открывается сразу;
  - несколько — программа показывает нумерованный список с размером и датой и просит выбрать номер;
  - подпапки не просматриваются.

## Какие файлы открываются

| Вариант | Что делает программа |
|---|---|
| KML с namespace `opengis.net/kml/2.2`, `earth.google.com/kml/2.x` или без него | читает как есть |
| Корень `kml → Document`, `kml → Folder` или сразу `Document` | метки ищутся по всему файлу |
| UTF-8 (с BOM и без), UTF-16, Windows-1251 | кодировка определяется автоматически, в том числе при неверном заголовке |
| Пустые строки перед `<?xml` | отбрасываются |
| Неэкранированный `&`, префикс `gx:` без объявления | исправляются при чтении, в лог пишется предупреждение |
| KMZ, где главный KML назван не `doc.kml` | берётся `doc.kml` из корня, иначе первый KML из корня архива |
| KMZ с расширением `.kml` или KML с расширением `.kmz` | тип определяется по содержимому |
| Файл только со ссылкой `NetworkLink` | отказ с подсказкой: сохраните карту через «Сохранить место как» |

Исходный файл при этом никогда не изменяется.

## Поиск меток

Для каждого введённого названия программа действует по шагам, до первого результата:

1. **Точное название.** Регистр учитывается; лишние пробелы (по краям, двойные, неразрывные) игнорируются.
2. **Номер в начале названия.** Название метки начинается с введённого текста, а следом идёт
   разделитель: `_`, пробел, `-` или `.`. Ввод `10` найдёт `10_Retransliator`,
   но не `100_Zdanie` и не `10А`.
3. **Маска**, если в названии есть символы `*`, `?` или `[`:

| Маска | Значение | Пример |
|---|---|---|
| `*` | любое количество любых символов | `10*` → `10`, `100`, `10А` |
| `?` | ровно один любой символ | `1?` → `10`, `11`, `1А` |
| `[...]` | один символ из набора | `1[05]` → `10`, `15` |

Названия, по которым ничего не найдено, программа перечисляет отдельно.
После поиска выводится строка «Запросов: X, найдено меток: Y» — по ней видно, всё ли нашлось.

## Формат пакетного ввода меток

В пакетном режиме названия вводятся в одной строке:

- через запятую: `10,11,12`
- через двоеточие: `10:11:12`
- через точку с запятой: `10;11;12`
- комбинированно: `10:11,12;13`

Строку из Excel можно вставлять без чистки: знак `=`, фигурные скобки и кавычки
программа уберёт сама (`={"10":"11":"12"}` → `10`, `11`, `12`).
Метку, в названии которой есть запятая, двоеточие или точка с запятой, вводите в интерактивном режиме.

## Папки и метки

- Каждая метка попадает **только в одну папку**. Если метку добавить во вторую папку,
  она переедет туда — программа сообщит, сколько меток перенесено.
- Чтобы завершить набор папок, нажмите `ENTER` вместо имени папки и подтвердите сохранение,
  либо ответьте «нет» на вопрос «Создать еще одну папку?».
- Перед сохранением выводится итог: папки и число меток в каждой.

## Результирующий KMZ-файл

- Создаётся рядом с исходным: `input.kmz` или `input.kml` → `input_groups.kmz`.
- Существующий файл **не перезаписывается**: следующий результат получит имя
  `input_groups_2.kmz`, затем `input_groups_3.kmz`.
- Внутри архива:
  - `doc.kml` со структурой `<kml>` → `<Document>` → `<Folder>` → `<Placemark>`;
  - общие стили исходного документа (`Style`, `StyleMap`, `Schema` с атрибутом `id`);
  - для KMZ — все вложения исходного архива (иконки из `files/` и т.п.);
  - для KML — иконки, лежащие рядом с исходным файлом. Если иконки нет на диске,
    в лог пишется предупреждение.
- Метки переносятся без изменений. В частности, скрытые в исходнике метки
  (`<visibility>0</visibility>`) останутся скрытыми — отметьте папку галочкой в Google Планета Земля.

## Логирование

- Логи пишутся в файл `kml_manager.log` в текущей директории.
- В консоль выводится только текст сообщений; подробности ошибок остаются в файле лога.

## Команды и обработка ошибок

- `!cancel` — отмена текущего шага; на вводе имени папки — завершить набор и сохранить файл.
- `!exit` — немедленное завершение программы **без сохранения** набранного.
- При ошибках чтения, разбора или записи вы получаете понятное сообщение и запись в логе.
- После непредвиденной ошибки окно не закрывается, пока вы не нажмёте `ENTER`.
